# Meridian 0.6 — Living Matter (proposed milestone)

**Status:** Planned, not implemented. **Delivery strategy:** prototype first. **Baseline:** Meridian 0.5.0. **Target:** 0.6.0 experimental. **Estimate:** 3 weeks prototyping + 2 weeks formative evaluation, dependent on available effort and participants.

## Goal

Find a coherent, recognisable physical interaction vocabulary for Meridian through tangible experiments in magnetism, elasticity, fluidity, gravity/inertia and atmospheric glass. Preserve the working 0.5 reference and treat all new effects as optional experimental capabilities. Scientific evidence and product adoption remain separately scoped.

## End-of-milestone acceptance

1. **Three independently usable browser prototypes**: Living Controls, Living Workspace, Living Environments.
2. **Six versioned experiment records**: attraction, merging, elastic press, spatial continuity, viscous deformation and glass/refraction.
3. **Conventional comparison** for each behaviour: effect ON/OFF with equivalent semantic operations.
4. **Accessible fallback** demonstrated for keyboard, touch where applicable, reduced motion, reduced transparency, forced colours/increased contrast and unsupported effects. No loss of meaning or actionable UI.
5. **Performance report** with observed interaction latency/frame behaviour on named browsers/devices, not unsupported universal targets.
6. **Preliminary user feedback** with protocol, participant/task context, uncertainties and explicitly limited claims; where participants are unavailable, mark validation pending.
7. **Promotion decisions**: reject / revise / continue in Lab / candidate for Design; no automatic stable-token export.
8. **Regression:** 0.5 reference remains buildable and existing CI remains green.

## Experiments

| ID | Experiment | Mechanism to explore | Control version | Primary concern |
| --- | --- | --- | --- | --- |
| LM-01 | Magnetic attraction | Cosmetic pointer-local displacement, proximity feedback | Static hover/focus | Stable hit area; no pointer-escaping UI |
| LM-02 | Liquid merging/separation | Visual grouping and continuity between elements | Discrete selection/transition | Clear identities and correct focus/DOM order |
| LM-03 | Elastic contact/rebound | Compression and settling after direct contact | Instant state change | Never delay command execution |
| LM-04 | Gravity and inertia | Spatially coherent arrivals, movement and release | Non-spatial navigation | Orientation; no gratuitous parallax |
| LM-05 | Viscosity and morphing | Form resistance, shape transformation | Immediate resize/swap | Layout stability, drag alternatives |
| LM-06 | Atmospheric glass | Layering, blur, controlled highlights | Opaque surface | Legible composited text and controls |

Each experiment must be accompanied by its own research hypothesis and falsification conditions in [hypothesis registry](../../research/hypotheses/living-matter.md).

## Three prototype briefs

### Living Controls

**Target tasks:** locate and activate a primary control; switch segmented selection; toggle a choice; recover from disabled/loading/error. **Effects:** LM-01, LM-02, LM-03. **Core validation:** recognition, hit target stability, perceived responsiveness, keyboard/touch equivalence. **Excluded:** production component API redesign.

### Living Workspace

**Target tasks:** open a floating panel, navigate between related views, rearrange an optional surface, dismiss an overlay and recover focus. **Effects:** LM-04, LM-05, LM-06. **Core validation:** spatial continuity, layout stability, actual completion and focus restoration. **Excluded:** persistent application data or heavy rendering dependencies unless experiment demands them.

### Living Environments

**Target tasks:** change environment and appearance, complete the same reading/control task and choose an opaque/minimal presentation. **Families for initial exploration:** Forest, Ocean, Desert, Alpine, Storm, Celestial; do not imply all are production themes. **Core validation:** semantic-role preservation, product-brand autonomy, colour legibility. **Excluded:** generating every cross-product combination or claims of circadian treatment.

## Implementation boundaries

- Do not modify existing 0.5 components/tokens until a reviewed proposal demonstrates need.
- Lab uses isolated CSS/TypeScript/JS modules and explicit experiment toggles.
- Begin with transforms, opacity and SVG when suitable; WebGL/WebGPU require an experiment-specific rationale and fallbacks.
- Never animate essential text readability or focus order.
- Use precise interaction semantics for all alternate input modes; hover alone is insufficient.
- Allow system preferences to constrain effects; never infer medical or cognitive condition from preferences.
- Keep all research records anonymous/minimal, obtain consent for actual participant studies and do not publish personal participant data.
- Do not migrate Lexis, Verbalis, NotUX, Framio or Ambientis in 0.6.

## Research and review gates

**Gate A — Concept review:** clear purpose, why this effect vs simpler alternative, task examples, failure risks.

**Gate B — Prototype review:** functional accessibility fallback, stable input semantics, measured runtime costs.

**Gate C — Formative study:** preregistered or pre-written protocol, relevant participants if available, results including counterexamples and limitations.

**Gate D — Promote/defer:** BSDL ethical check, rationale, implementation cost, design-system compatibility, explicit owner approval.

## Definition of done

0.6 is a **publicly identifiable experimental Lab milestone**, not a published stable component API. Claim success only for working demonstrations and evidence actually obtained. A task that needs another version remains explicitly open.

## Future series (not 0.6 scope)

0.7 foundations/environment contract → 0.8 React alpha → 0.9 controlled product pilots → 1.0 stable web Core/React. SwiftUI and broader contributor ecosystem follow when web contracts are reliable.
