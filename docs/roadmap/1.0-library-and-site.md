## Answer first

Meridian already has most of the parts: a rich Figma file, a sync pipeline (plugin, named-version workflow, draft PRs, Pages deploy) and a reference site. What it lacks is **one loop that every change must pass through**. Today Figma has moved ahead of GitHub, the repo's map of Figma points at a page structure that no longer exists, and colour is defined in four overlapping places. The plan below closes that loop first, then restructures Figma into library, website and lab files, then builds the website from the exported data.

## 1. Audit findings (EXISTING)

### 1.1 Figma file structure

- Six pages: Home, Develop, Foundations, Style, Components, Archive. This already follows Material 3's top navigation (Get started, Develop, Foundations, Styles, Components). Style / Colour is even split into System, Roles, Schemes, Static, Dynamic, Advanced, which mirrors Material's colour chapter.
- Foundations: Overview, Accessibility, Content Design, Devices, Design Token, Interactions, Layout. Style: Colour, Elevation, Icons, Motion, Shape, Spacing, Typography, plus the Liquid Glass and Environment review frame.
- Develop holds documentation frames still titled "Meridian 0.3 / System handbook" (Lifecycle, Definition of ready, Source and flow) while the library is 0.5 and the Lab is 0.6. Develop / Mobile is an empty placeholder.
- Components: 62 top-level sets and components (402 component nodes with variants). The state model is consistent and the descriptions are strong. Naming is not: `Meridian / List item` beside `List`, `Dialog` as both a component (5:187) and a set (45:2339), and 16 `Universal / ...` items carried over from the prototype.
- Symbols: 104 sets and 434 variants on the Style page (80 Universal, 24 reference, project and mark masters); every set has Outline, Filled, Colour and Duotone, and 18 also have Material.
- Archive: 11 sections, including a 145-item provenance register and 425 pre-rebuild symbol nodes.

### 1.2 Variables and tokens

- 14 collections, 1,804 variables. One collection, "Collection", is empty.
- **Colour is defined four times:** 0.5 Colour (Grass, Paper, Core × Dawn/Dusk) with Project Colour (Parallel, Canvas, Gallery × Dawn/Dusk), split because of the ten-mode limit; 0.6 Environment (10 modes) resolved through Appearance (Dawn/Dusk, 470 internal variables); Living Environments 0.6 (five environments × Dawn/Dusk as ten modes of literal hex); and the 0.6 Lab Forest collection (12 variables).
- Primitives mixes true primitives with theme palettes (`paper/dawn/...`, `project/parallel/light/...`) and 269 swatches named by their own hex value (`environment/swatch/e9ecedff`), which breaks the moment a value changes.
- Code syntax uses seven prefixes: `--meridian-*`, `--md-*`, `--md-source-*`, `--md-primitive-*`, `--material-*`, `--optics-*`, `--fr-*`.

### 1.3 Figma to GitHub sync and links

- The pipeline exists, in both directions. GitHub to Figma: `design/figma/generated/tokens.json` and `site/content.json` are the edit points, and the plugin's **Apply GitHub values** (or live mode while it is open) writes them into native variables and mapped text layers, refusing to overwrite when both sides changed. Figma to GitHub: `figma-sync.yml` turns named versions into layer diffs, previews, a handoff issue and a draft PR (plus a six-hourly check); `forest-figma-handoff.yml` does the same for the Forest Lab; `pages.yml` deploys the site. An optional webhook receiver (`api/figma-webhook.mjs`) exists, but the README says none has been deployed or registered.
- The gap is coverage, not mechanism: `tokens.json` holds 168 names, all present in Figma, but none of the 0.6 Environment, Appearance, Material or Icon Foreground collections.
- **The plugin's token sync cannot read the current file** (found in phase 1): its capture treats the 0.6 collections as 0.5 profile collections and throws, and the Motion collection now holds nine `motion/liquid/*` tokens that GitHub lacks. Confirmed by running the repo's capture code on the exported structure, not inside Figma.
- **Figma is ahead of GitHub.** The 2026-11-01 diff shows changes that never reached the repo: new motion values (72 mismatches), Aurora's new violet-blue palette, unified glass alpha, the Material and Icon Foreground collections, 23 Environment roles, four extra icon treatments and six master symbols.
- **Links are stale.** Of the 147 Figma node IDs the repo references (`design/figma/config.json`, `design/meridian/figma-manifest.json`, `design/figma/forest-lab.json`), 8 no longer exist and 59 now sit on the Archive page. The manifest still describes the old 12-page layout ("00 · Meridian · Start" to "11 · Meridian Paper").
- **Change history is incomplete.** `CHANGELOG.md` stops at an "Unreleased — 2026-10-16" entry, and none of the Figma-side changes above are logged. Named-version history is not visible through the plugin API, so I could not check what was named or described. **UNVALIDATED.**

### 1.4 Repo and website

- Vite reference site (`index.html`, `src/pages.js`, `styles/*.css`), shared copy in `site/content.json`, token build scripts, Playwright and axe tests, ADRs, a roadmap, research records and a Lab with 0.6 prototypes.
- Component knowledge is spread across `design/meridian/components.json` (30 recipes), `docs/components.md` (guidance for Button, Field, product integration, profiles and list feedback, glass actions), four `universal-*.json` files (92 families) and Figma descriptions. 69 of the 92 Universal families have no master on the Components page.

## 3. The change loop (DECIDED principle; mechanics PROPOSED)

1. **GitHub-first changes (tokens, copy, recipes).** Keep the existing edit points (`design/figma/generated/tokens.json`, `site/content.json`) and the plugin's **Apply GitHub values**. Extend the token source and the plugin to the collections that are public in 1.0 (2.4), so the 0.6 colour layer stops being Figma-only.
2. **Figma-first changes (components, specs, symbols, page designs).** Save a named version with a short description template (type, summary, issue). `figma-sync.yml` regenerates `design/figma-export/` (inventory, screenshots, per-variant symbol SVGs, variable snapshot from the plugin), writes the diff and a changelog entry from the version description, and opens a draft PR linked to the Figma nodes.
3. **Symbols.** Export per-variant SVGs in CI through Figma's REST image endpoint, which takes many node IDs per request. It needs a Figma personal access token as a repo secret. **UNVALIDATED** for your plan tier.
4. **Integrity checks in CI.** Every Figma node ID in the manifests must exist and must not sit in the archive; the token checksum must match the last plugin publication; the site's axe and Playwright tests run on every PR.
5. **Links both ways.** Each Figma component description ends with Docs, Code and Status links; each repo recipe carries its Figma node ID and key; each site page has an "Open in Figma" link.
